# AI 기반 주차 안내 시스템

# ㅇㅇ

## 1. 프로젝트 개요

기존에 개발한 **AI 차량 번호판 인식 모델**을 활용하여 차량에 적합한 주차 공간을 자동으로 배정하고, Flask 웹 대시보드에서 주차장 도면과 실시간 주차 상태를 보여주는 시스템이다.

### 핵심 목표

1. AI 모델로 차량 번호판을 인식한다.
2. 인식한 차량 번호로 `vehicles.csv`에서 차량 정보를 조회한다.
3. 차량 종류와 너비를 기준으로 적합한 주차 공간 유형을 결정한다.
4. 적합한 빈 주차 공간 중 하나를 무작위로 배정한다.
5. 차량 번호와 주차 공간 번호를 Python 메모리에 연결하여 저장한다.
6. Flask 웹 대시보드에서 주차장 도면과 현재 주차 상태를 표시한다.
7. 배정된 공간을 색상으로 안내한다.
8. 출차 시 차량 번호를 이용하여 연결된 공간만 빈 공간으로 변경한다.

---

## 2. 전체 시스템 구조

```text
차량 진입
   ↓
기존 AI 번호판 인식 모델
   ↓
차량 번호 정규화
   ↓
vehicles.csv 조회
   ↓
차량 종류 + 차량 너비 확인
   ↓
차량 유형 분류
   ├─ 경차 → K
   ├─ 비경차 + 너비 >= n → B
   └─ 비경차 + 너비 < n → S
   ↓
parking.csv에서 공간 종류 확인
   ↓
parking_status에서 빈 공간 확인
   ↓
차량 유형과 공간 유형이 같은 공간만 후보로 선정
   ↓
후보 중 하나를 무작위 배정
   ↓
parking_status 변경
assigned_cars에 차량-공간 연결 저장
   ↓
Flask 웹 대시보드에 결과 전달
```

출차는 다음과 같이 처리한다.

```text
차량 출차
   ↓
번호판 인식
   ↓
assigned_cars 조회
   ↓
차량에 연결된 주차 공간 확인
   ↓
parking_status에서 해당 공간을 빈 공간으로 변경
   ↓
assigned_cars에서 차량 정보 삭제
   ↓
웹 화면 갱신
```

## 4. CSV 데이터

### 4.1 vehicles.csv

차량의 고정 정보를 저장한다.

필드:

- 차량 번호
- 차량 종류
- 차량 너비

예시:

```csv
차량 번호,차량 종류,차량 너비
12가3456,일반 차량,1800
34나5678,경차,1500
```

차량 너비의 단위는 **mm**로 통일한다.

이 파일에는 현재 주차 상태를 저장하지 않는다.

---

### 4.2 parking.csv

주차 공간의 고정 정보를 저장한다.

필드:

- 주차 공간 번호
- 주차 공간 종류

예시:

```csv
주차 공간 번호,주차 공간 종류
A1,B
A2,S
A3,K
B1,B
B2,S
```

주차 공간 번호 자체로 공간 종류를 판단하지 않는다.

예를 들어 `A1`이라는 이름만 보고 B형이라고 판단하지 않고 반드시 `parking.csv`의 정보를 사용한다.

## 5. 주차 공간 종류

주차 공간 종류는 세 가지이다.

| 유형 | 의미 |
|---|---|
| B | 대형 차량용 공간 |
| S | 소형 차량용 공간 |
| K | 경차 전용 공간 |

---

## 6. 차량 분류 규칙

### 경차

차량 종류가 경차라면 차량 너비와 관계없이:

```text
경차 → K
```

로 분류한다.

### 일반 차량

경차가 아닌 차량은 차량 너비를 기준값 `n`과 비교한다.

```text
너비 >= n → B
너비 < n → S
```

`n`은 실제 주차장 환경에 맞춰 결정해야 한다.

현재 `n`은 확정되지 않았으므로 코드에서 설정값으로 관리한다.

임의의 값으로 확정하지 않는다.

---

## 7. Python 메모리에서 관리하는 정보

현재 주차 상태는 CSV에 저장하지 않고 Python 메모리에서 관리한다.

### parking_status

각 주차 공간의 현재 상태를 저장한다.

예:

```python
parking_status = {
    "A1": "빈 공간",
    "A2": "점유",
    "A3": "빈 공간"
}
```

역할:

```text
주차 공간 → 현재 상태
```

---

### assigned_cars

차량 번호와 배정된 주차 공간을 연결한다.

예:

```python
assigned_cars = {
    "12가3456": "A2"
}
```

역할:

```text
차량 번호 → 배정된 주차 공간
```

이 자료구조는 출차할 때 반드시 필요하다.

두 자료구조는 서로 일치해야 한다.

예:

```text
assigned_cars["12가3456"] = "A2"

parking_status["A2"] = "점유"
```

## 8. 프로그램 시작 시 초기화

프로그램을 시작하면 다음 순서로 처리한다.

1. `vehicles.csv`를 읽는다.
2. `parking.csv`를 읽는다.
3. CSV 필수 필드를 검증한다.
4. 차량 번호 중복 여부를 확인한다.
5. 주차 공간 번호 중복 여부를 확인한다.
6. 차량 너비가 올바른 값인지 확인한다.
7. 공간 종류가 `B`, `S`, `K` 중 하나인지 확인한다.
8. 모든 주차 공간을 빈 공간으로 초기화한다.
9. `assigned_cars`를 비운다.
10. Flask 서버를 실행한다.
11. 웹 대시보드에 전체 주차장 도면을 표시한다.

프로그램 재시작 시 이전 주차 상태를 복구하지 않는다.

즉, 프로그램이 시작되면 모든 공간이 비어 있다고 가정한다.

---

## 9. 입차 처리

차량이 진입하면 다음 순서로 처리한다.

### 1단계. 번호판 인식

기존 AI 번호판 인식 모델을 사용하여 차량 번호를 얻는다.

### 2단계. 번호판 확인

인식 결과를 정규화하고 차량 번호를 확인한다.

### 3단계. 이미 주차된 차량인지 확인

```text
assigned_cars에 차량 번호가 존재하는가?
```

존재한다면 새로운 공간을 배정하지 않는다.

기존에 배정된 공간을 안내한다.

### 4단계. 차량 정보 확인

`vehicles.csv`에서 차량 번호를 검색한다.

등록되지 않은 차량이라면 배정을 중단하고 미등록 차량으로 처리한다.

### 5단계. 차량 유형 결정

차량 종류와 너비를 이용하여 `K`, `B`, `S` 중 하나로 분류한다.

차량 정보가 불완전하거나 잘못된 경우 임의로 분류하지 않는다.

### 6단계. 빈 공간 검색

`parking_status`에서 현재 빈 공간을 찾는다.

### 7단계. 적합한 공간만 선택

차량 유형과 주차 공간 유형이 정확하게 일치하는 공간만 후보로 만든다.

예:

```text
차량 유형 = B

A1 → B + 빈 공간 → 후보
A2 → S + 빈 공간 → 제외
A3 → B + 점유 → 제외
```

### 8단계. 무작위 배정

후보가 여러 개라면 그중 하나를 무작위로 선택한다.

### 9단계. 공간 배정 및 중복 배정 방지

배정된 공간을 차량 번호와 연결해 저장한다. **이 단계에서는 아직 `parking_status`를 점유 상태로 바꾸지 않는다.** 차량이 안내받은 공간에 실제로 도착한 뒤 차량 내부 내비게이션의 `주차 완료` 버튼을 눌러야 점유 상태가 된다.

```python
assigned_cars["12가3456"] = "A1"
```

배정만 받은 공간도 다른 차량에 중복 배정하면 안 된다. 따라서 빈 공간을 찾을 때 `parking_status`가 빈 공간인지뿐 아니라, 해당 공간이 다른 차량의 `assigned_cars`에 이미 배정되어 있는지도 확인한다.

### 10단계. 웹 화면 안내

차량 내부 내비게이션에서 배정 공간과 길 안내 경로를 도면 위에 표시한다. 안내 중인 공간은 초록색으로 표시할 수 있다. 관리자 화면에는 차량 번호, 차종, 너비와 배정 상태를 표시한다.

**초록색 안내가 시작되었다는 이유만으로 공간을 점유 상태로 바꾸거나, 일정 시간이 지난 뒤 자동으로 점유 상태로 바꾸지 않는다.**

---

## 10. 출차 처리

출차할 때는 차량 번호를 이용하여 정확한 공간을 찾아야 한다.

### 처리 순서

1. 출구에서 번호판을 인식한다.
2. `assigned_cars`에서 차량 번호를 검색한다.
3. 기록이 없다면 아무 공간도 변경하지 않는다.
4. 기록이 있다면 연결된 공간 번호를 확인한다.
5. 해당 공간을 `빈 공간`으로 변경한다.
6. `assigned_cars`에서 차량 정보를 삭제한다.
7. 웹 화면에서 해당 공간을 흰색으로 표시한다.

주차 완료 버튼을 누르기 전에 출차한 차량이라면 공간 상태는 원래 빈 공간이므로 그대로 빈 상태를 유지한다. 이미 주차 완료 처리된 차량이라면 그 차량에 연결된 정확한 공간만 빈 공간으로 변경한다.

예:

```python
assigned_cars = {
    "12가3456": "A1"
}
```

출차하면:

```python
parking_status["A1"] = "빈 공간"
del assigned_cars["12가3456"]
```

가 된다.

다른 공간을 임의로 비우면 안 된다.

## 11. 웹 대시보드

웹 대시보드는 주차 안내 화면과 관리자 화면 등 여러 화면으로 구성할 수 있다.

Flask 서버 하나를 사용하고 여러 URL을 제공하는 방식으로 구성할 수 있다.

예:

```text
http://127.0.0.1:5000/guide
http://127.0.0.1:5000/admin
```

두 브라우저 창을 동시에 열어 사용할 수 있다.

두 화면은 서로 다른 주차 상태를 가지는 것이 아니라 동일한 Python 메모리의 `parking_status`와 `assigned_cars`를 사용한다.

## 12. 차량 내부 내비게이션 화면

차량 내부 화면은 운전자가 배정된 주차 공간까지 이동할 수 있도록 안내한다.

구성 요소:

- 주차장 도면
- 도면 위에 표시되는 길 안내 경로와 배정된 공간
- `주차 완료` 버튼
- 전체 주차장 도면과 미리 정한 도면 일부를 전환하는 버튼

### 도면 전환

운전자는 버튼을 눌러 전체 도면과 미리 정한 확대 구역을 전환할 수 있다. 확대는 카메라 영상이 아니라 웹 화면의 주차장 도면에 적용한다. 도면은 자동으로 전체 화면으로 돌아가지 않고, 사용자가 직접 전환 버튼을 눌러야 한다.

### 색상

| 색상 | 의미 |
|---|---|
| 초록색 | 차량에 배정되어 길 안내 중인 공간 |
| 빨간색 | 주차 완료 버튼을 눌러 점유 처리된 공간 |
| 흰색 | 비어 있고 다른 차량에 배정되지 않은 공간 |

### 주차 완료 버튼 동작

1. 운전자가 배정된 공간에 도착한다.
2. 차량 내부 내비게이션에서 `주차 완료` 버튼을 누른다.
3. 서버가 해당 차량 번호와 배정 공간의 연결을 확인한다.
4. 연결이 유효하면 그 공간의 `parking_status`를 `점유`로 변경한다.
5. 관리자 화면과 차량 내부 내비게이션에 변경된 상태를 반영한다.

버튼을 누르기 전에는 배정 공간을 점유 상태로 변경하지 않는다. 버튼을 누르기 전까지 해당 공간은 다른 차량에 배정되지 않도록 예약된 상태로 취급한다.

---

## 13. 관리자 화면

관리자는 전체 주차장 현황과 차량 진입 정보를 확인한다.

구성 요소:

- 전체 주차장 도면
- 미리 정한 구역으로 확대된 도면
- 전체 도면과 확대 도면을 전환하는 버튼
- 주차 공간별 주차 여부 및 상태
- 차량 진입 시 차량 번호판, 차종, 너비
- 차량별 배정 공간과 배정/주차 완료 여부

관리자 화면에서도 도면 전환은 사용자가 버튼으로 직접 조작한다. 관리자 화면과 차량 내부 내비게이션은 서로 다른 상태를 따로 저장하지 않고 동일한 `parking_status`와 `assigned_cars`를 사용한다. 차량 정보는 `vehicles.csv`에서 조회한 번호판, 차종, 너비를 표시한다.

---

## 14. 주차장 도면

직접 제작한 주차장 도면 이미지를 사용한다.

도면 위에 주차 공간을 표시하고 Python의 공간 ID와 연결한다.

예:

```text
도면의 A1
   ↕
Python의 "A1"
```

도면 구현 방법은 다음 중 하나를 사용할 수 있다.

- 도면 이미지 + HTML 요소 겹치기
- SVG 도면 사용

현재 도면의 실제 크기와 주차 공간 좌표는 확정하지 않았다.

따라서 임의의 좌표를 사용하지 않는다.

---

## 15. 고정 구역 확대

차량이 배정되면 카메라 영상을 확대하는 것이 아니라 **웹페이지에서 미리 지정한 도면 구역을 확대**한다.

확대 구역은 미리 정해진 고정 영역이다.

사용자가:

```text
전체 도면으로 돌아가기
```

버튼을 눌러야 전체 도면으로 돌아간다.

자동으로 전체 도면으로 돌아가지 않는다.

## 16. 복수 차량 처리

여러 차량이 연속으로 진입할 수 있으므로 차량별 이벤트를 순차적으로 처리한다.

예:

```text
차량 A 진입
   ↓
주차 공간 배정

차량 B 진입
   ↓
주차 공간 배정

차량 C 진입
   ↓
주차 공간 배정
```

중요한 점은 한 차량의 안내 처리 때문에 Python 서버 전체가 멈추면 안 된다는 것이다.

따라서 필요하면 이벤트 대기열과 비동기적인 웹 화면 처리를 사용한다.

먼저 배정된 공간이 다른 차량에게 중복 배정되지 않도록, 공간 배정 시점부터 해당 공간을 다른 차량의 후보에서 제외한다. 다만 `parking_status`를 `점유`로 바꾸는 시점은 차량 내부 내비게이션에서 `주차 완료` 버튼을 누른 때이다.

## 아두이노 우노 주차 상태 알림

주차 공간이 `점유` 상태로 변경되면 Python 프로그램이 아두이노 우노 보드로 해당 공간 번호와 점유 상태를 전송한다.

### 전송 시점
- 차량이 공간을 배정받았을 때는 점유 신호를 보내지 않는다.
- 차량 내부 내비게이션 화면에서 `주차 완료` 버튼을 눌러 공간 상태가 `점유`로 변경되는 순간, 해당 공간 번호와 `점유` 상태를 아두이노 우노로 전송한다.
- 공간이 다시 빈 공간으로 변경되는 경우에도 아두이노에 빈 공간 상태를 알릴 수 있도록 같은 형식으로 전송한다.

### 신호 형식 예시
USB 시리얼 통신을 사용하는 경우 한 줄에 하나의 메시지를 보내는 방식으로 구성할 수 있다.

```text
A1,OCCUPIED
A2,EMPTY
```

- 첫 번째 값: 주차 공간 번호
- 두 번째 값: 공간 상태 (`OCCUPIED` 또는 `EMPTY`)

위 메시지는 통신 형식의 예시이며, 실제 아두이노 코드와 Python 코드에서 동일한 형식을 사용해야 한다. 아두이노 우노의 포트 번호와 통신 속도는 실제 연결 환경에 맞춰 설정한다.

### 구현 시 주의 사항
- Python에서 공간 상태가 실제로 변경된 뒤 해당 공간 번호와 상태를 전송한다.
- 다른 공간의 상태를 잘못 전송하지 않도록 변경된 공간 번호를 정확히 사용한다.
- 시리얼 포트 연결 실패나 전송 오류가 발생해도 Flask 웹 서버가 멈추지 않도록 오류를 처리한다.
- 아두이노가 메시지를 받으면 공간 번호와 상태를 분리해 처리할 수 있도록 줄바꿈 문자로 메시지를 구분한다.

## 22. 알려진 한계

### 번호판 인식 오류

AI 번호판 인식 모델이 잘못된 번호를 인식할 수 있으므로 결과 검증이 필요하다.

### 실제 주차 여부

번호판 인식만으로 차량이 실제 주차 공간에 주차했는지는 확인할 수 없다.

별도의 주차 센서가 없다면 빨간색 상태는 시스템상의 점유 상태를 의미한다.

### 프로그램 재시작

현재 주차 상태를 파일에 저장하지 않는다.

따라서 프로그램을 재시작하면 모든 공간이 빈 상태로 초기화된다.

실제 주차장에 차량이 남아 있다면 실제 상태와 시스템 상태가 달라질 수 있다.

### 입차와 출차 구분

번호판 인식 모델만으로 차량이 입차 중인지 출차 중인지 자동으로 판단한다고 가정하지 않는다.

필요하다면 입구/출구 카메라를 분리하거나 별도의 입·출차 판별 기능을 사용한다.

## 25. 개발 원칙

1. 기존 AI 번호판 인식 모델을 사용한다.
2. 번호판 인식 모델을 처음부터 새로 개발하지 않는다.

6. 출차 시 반드시 연결된 공간만 해제한다.
7. 적합한 공간 유형이 정확히 일치해야 한다.

10. 적합한 공간이 없으면 배정하지 않는다.
11. 차량 정보가 불확실하면 임의로 분류하지 않는다.
12. 안내 화면의 갱신 때문에 서버 전체를 중단하지 않는다.
13. 차량 내부 내비게이션에서 `주차 완료` 버튼을 눌렀을 때만 해당 공간을 점유 상태로 변경한다.
14. 여러 차량의 이벤트를 잃지 않도록 처리한다.
15. 실제 주차 여부와 시스템상의 점유 상태를 구분한다.
16. 프로그램 재시작 시 상태가 초기화된다는 점을 유지한다.
17. 확인되지 않은 파일명, 함수명, 모델 인터페이스를 임의로 만들지 않는다.
18. 기존 코드의 기능을 임의로 변경하지 않는다.
19. 구현되지 않은 기능을 구현 완료라고 표현하지 않는다.
